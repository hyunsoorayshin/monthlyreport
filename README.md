# monthlyreport

A small pandas/matplotlib pipeline that turns per-class weekly score
spreadsheets into a one-page monthly progress report (PNG) for each student,
plus a short "heads-up" CSV of students whose average sits near a level
boundary. Two cohorts with different subject sets share the same shape of
pipeline; a third script produces a level-up advice sheet for a single
student. Everything in this repository runs on the synthetic sample data that
ships with it.

## Why I built it

I was teaching at an English academy in Seoul and every month I had the same
chore: open a stack of weekly score spreadsheets, work out where each student
stood relative to their level, spot who was drifting toward a boundary, and
write something useful for each of them. Doing that by hand was slow and
inconsistent from one month to the next. I wanted a faster, more repeatable
way to get from the weekly CSVs to a per-student report and a list of who
needed a closer look. I built this on my own time as a side project.

## What this is not

- It is **not** official infrastructure of any school or academy, and it was
  **not** an assigned work product.
- The repository contains **no real student data**. Every name, score, class
  code and template sentence here is synthetic, generated by
  `make_sample_data.py`.
- The level / cutline scheme (levels 2-4 plus probation, percentile cutlines)
  is a generic placeholder. Any resemblance to a specific institution's rules
  is not intended.

## How the "level change probability" works (plain answer)

It is a hand-set heuristic, not a fitted or trained model. There are no
learned parameters anywhere in this repository.

The number shown on a report is

```
probability = base + (max - base) * (1 - exp(-k * margin))
```

where `margin` is the student's distance in points from a cutline, and
`base` (5 for an upward move, 10 for a downward one), `max` (70) and
`k = 0.5` are constants I chose by hand so that the curve saturates at a
sensible-looking value. The function is `calculate_level_probability` in
`cohort_a/monthly_report.py` and `cohort_b/monthly_report.py` (the two copies
are identical). If the student is on the "safe" side of every cutline the
report just says "stable" and shows no percentage.

The cutlines themselves are simple percentiles of the cohort's per-student
overall averages: the 85th percentile for the Lv2 boundary, the 45th for Lv3,
and the 5th for Lv4 / probation (`build_master.py` in each cohort folder).
Cohort B additionally bootstraps those percentiles to draw a "borderline"
band around each line; the point estimate is still the percentile.

The trend "slopes" in the level-up report (`levelup_report.py`) are ordinary
least-squares lines through each student's weekly scores (`numpy.polyfit`,
degree 1), used descriptively. The signal labels ("Rising", "Potential",
"Volatile", "Plateau", "Declining") are fixed thresholds on that slope and on
the coefficient of variation of the scores. Nothing in this repo is trained
on data.

## How to run

Tested with Python 3.9 on macOS. The reports contain Korean labels, so a font
with Hangul glyphs must be installed (the scripts try Apple SD Gothic Neo,
AppleGothic, Arial Unicode MS, Malgun Gothic and NanumGothic in turn).

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# Optional: regenerate the synthetic sample data and placeholder templates
python3 make_sample_data.py

# Cohort A: master CSV + cutlines, then per-student reports
python3 cohort_a/build_master.py
python3 cohort_a/monthly_report.py

# Cohort B: same, with a prior/current period split and radar + trend panels
python3 cohort_b/build_master.py
python3 cohort_b/monthly_report.py

# Level-up advice sheet for one Cohort B student (name as it appears in the master CSV)
python3 levelup_report.py "StudentA 학생A"
```

Outputs land next to the scripts and are git-ignored:
`Cohort?_Master.csv`, `Cohort?_Cutlines.csv`, `Cohort?_Monthly_Summary.csv`,
`Cohort?_Risk_List.csv` and `reports/<class>/<student>_report.png`.

Every script accepts `--data-dir`. For `build_master.py` it points at the
folder holding `student_list.csv` and `csv/` (default `sample_data/`), with
`--output-dir` for where the master and cutlines go. For `monthly_report.py`
and `levelup_report.py` it points at the folder holding the generated master
and cutline CSVs (default: the cohort folder). `cohort_b/build_master.py`
also takes `--cutoff YYYY-MM-DD` for the prior/current period boundary.

### Data conventions

- `student_list.csv`: `Class, Korean Name, English Name, Level`. `Level` is
  `2`, `3`, `4` or `P` (probation). **Lower number = higher level**; the code
  assumes this when it talks about moving "up" to Lv2 or "down" to Lv4.
- `csv/<class>.csv`: `Date, Name, <subjects...>`, dates as `m/d/yy`, `Name`
  as `"<English Name> <Korean Name>"`. Blank cells are skipped. Rows whose
  name starts with `*` are reference rows and are ignored.
- `cohort_a/comment_templates.csv`: `Subject, Score_Tier, stable, level_up,
  level_down, probation, expulsion`. The shipped file is a **placeholder**
  written by `make_sample_data.py`: generic sentences so the report's advice
  panel has something to show. Replace it with your own library; the report
  looks up `(subject, tier, status)` where tier is one of `top`, `above_avg`,
  `average`, `below_avg`, `bottom`.

See `architecture.md` for the data flow in more detail.
